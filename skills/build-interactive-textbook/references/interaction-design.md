# 交互思路与状态组织

## 从目标倒推操作

以“学生做完后能解释什么”为起点。先选简单、变量少的模型建立关系，再增加复杂模型检验迁移。电势差样题先用两块理想平行板；A、B 所处等势线清楚后，再换双球的弯曲等势线。

目标、可操作物、当前状态分别表达：目标放在图外固定提示区；实际箭头留在物体上；成功与错误用短句反馈。不能把两根同位置、相似色的箭头叠加当成目标对照。

同一概念的横、竖两个方向不必首屏并列。先保留本题主方向，其余放进进阶选项。图上只突出一个抓手，固定点标明不能拖；支持方向键微调时保持同一物理规则。

## 状态流

第一层：操作 → 可记录状态 → 冻结图与数据 → 保存判断。
第二层：读取该记录 → 填槽与组式 → 计算／纠错 → 解释与导出。

记录应有独立 id、时间、模型标识、坐标、单位、结果、第一层观察、第二层运算和批注。重新操作生成新记录；切模型不改写旧记录；进入第二层不能覆盖第一层判断。改变算式或槽值后，旧的“正确”反馈和继续按钮失效。

## 信息与操作顺序

首屏一张主图、一道问题、一个主要动作。实时图与记录图在同一区域切换。完整参数、其他方向、积分核验、批量粘贴和批注工具按需展开；展开内容不能遮住抓手或主要按钮。

失败反馈指出下一步，例如“当前受力朝下，移动 P 再试”；不要只显示红叉。定性判断可以暂时错误并留到下一层验证，不把所有问题做成猜关键词通关。

输入提供量名、符号与单位，批量粘贴明确顺序。数学输入使用受限解析器，不运行任意代码。取数、计算与图形共享状态；相机与渲染效果不进入物理模型。

## 可迁移而非照搬

力学可以先观察位移／形变，再用同状态计算；热学可以先观察温度分布，再读数验证。先写契约与核验，不复制静电场公式、球体或颜色含义。具体层数、模型数量和控件由章节目标决定。
