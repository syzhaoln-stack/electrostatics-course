# 验证、打包与发布

## 验收分三类

1. 模型：解析特例、单位与符号、边界和极限、独立积分或守恒核验。
2. 交互：真实拖动、错误方向、重试、切模型、二维／三维、取数冻结、输入错误、两层作答、批注与导出。
3. 交付：从独立目录启动，资源本地可用，依赖许可齐全；在线版本与提交一致。

验收报告记录日期、版本／提交、运行位置、视窗、通过项和未覆盖范围。数值测试、技术可用性、教师认可、真实学习效果分别说明。

只在实现改变、失败或疑虑未解决时扩大或重复测试。静态低风险文字修改不必生成逐字断言。

## 教师包

建议包含：可运行课堂与可编辑源码、必要运行环境、启动入口、简短使用指南、研讨依据、真实交流节选、逐图反馈表、Skill、核验记录。给出独立 Skill 压缩包，方便安装到其他项目。

制作说明要写清包含哪些媒体与源码。运行网页所需资源不等于 Blender／Manim／配音完整生产环境；缺少中间工程时不要称为完整制作环境。打包前剔除临时日志、进程编号、缓存、账户信息和教学无关私聊。

生成逐文件相对路径、大小和 SHA-256 清单；压缩后检查可解压。不要依赖原作者机器上的绝对路径。若附 Windows 运行时，注明架构、版本和许可；其他系统需相应运行环境。

## GitHub 展示

沿用现有仓库与部署方式。检查工作区，明确发布文件，不把无关制作草稿一起提交。先完成测试和构建，再在用户授权范围内推送。不要在 Skill 中假定允许自动公开教师录音、交流原文或本地压缩包。

等部署任务成功后访问实际公开地址，检查入口、资源和关键交互；源码提交成功不等于展示站点已更新。提供展示链接与源码／Skill 链接，并在包里记录版本与核验时间。若部署失败如实说明，不把旧页面称为最新版。
